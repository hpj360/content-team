# 制作统筹与独立审查契约（蒸馏）

> 面向 `showrunning` 的按需加载参考。蒸馏自公开短剧/影视协作套件的权责分离、交付门与审查机制，重构为可执行契约，非逐字引用。

## 一、邻接权责（谁决定什么）

编导是**入口路由 + 统筹**，不是所有内容的作者。各阶段有明确 owner，避免职责重叠：

| 阶段 | owner skill | 编导职责 |
|---|---|---|
| 小说/素材 | `novel-writing` | 定义改编价值与取舍 |
| 剧本 | `script-writing` | 定义单集目标与验收标准 |
| 资产设定 | （资产类 skill） | 定义一致性红线 |
| 分镜 | `storyboarding` | 定义视觉计划与节奏 |
| 导演呈现 | `directing` | 定义风格基调与终审 |
| 审查 | **独立审查者** | 组织并裁定 |

原则：**创作与审查分离**。参与当前版本创作的人/上下文不担任该版本的审查。

## 二、创作者决策与来源引用

- 每个关键决定记录：**决策内容 + 决策人 + 依据（来源/原文位置）**。
- 引用即溯源：改编、拆文、素材引用必须保留来源与位置。
- 决策不可隐式覆盖：下游若需改变上游决策，必须显式记录并回报。

## 三、连续性契约

跨集/跨阶段必须维护同一套契约，防止漂移：

- 人物：身份、外形、音色、关系状态（逐集）。
- 世界观：规则红线、时间线、道具与证据链。
- 视觉：Look Development 确定的色板、光色、风格锚点。
- 每集交付前对照契约自检，冲突项必须裁决。

## 四、交付门（不假装出片）

- 明确"当前拥有什么工具"决定交付层级：只有文本工具 → 交付剧本/资产规格/分镜/提示词；有生成工具 → 才进入生成。
- **dry-run 优先**：无生成能力时输出 dry-run 制作包，并标明卡在哪一个交付门。
- 未完成媒体检查前，不得把草稿描述为"可发布成片"。
- 交付包字段：剧本 / 资产说明 / 分镜 / 提示词 / 生成记录 / QC 报告 / 发布包。

## 五、跨集引擎

- Series Engine：连载结构、钩子升级路线、情绪配比、反派递进。
- 分集地图：从长篇材料按文件实际结构建立一次索引，逐集切片，支持断点续跑（每次只读当前集）。
- 钩子与升级：每集结尾钩子强度整体递增，避免中段疲软。

## 六、一致性宪法（红线示例）

```
consistency_rules:
  characters: [人设红线]
  world:      [世界观红线]
  visual:     [视觉基调]
```

- 红线写一次，逐集复用，逐字一致。
- 红线冲突时，编导裁决并记录；未裁决不得发布。

## 七、质量门（机器可验证）

- [ ] `positioning` / `format` / `style` 非空
- [ ] `episode_plan` ≥ 1 集，每集 `hook` 与 `cliffhanger` 非空
- [ ] `consistency_rules` 三类（人物/世界观/视觉）非空
- [ ] `assignment` 覆盖全部创作阶段，每项有可验证 `acceptance`
- [ ] 存在**独立审查**记录（非本版创作者）
- [ ] 交付门已声明（有/无生成工具，是否 dry-run）
