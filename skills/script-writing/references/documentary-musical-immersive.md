# 纪录片 / 音乐剧 / 沉浸式脚本（形态深度）

> `script-writing` 按需加载参考。三类"非标准叙事形态"的脚本规范——它们的共同点是
> **承载不在情节，而在信息 / 音乐 / 空间**。

## 一、纪录片脚本（三栏式）

```
| 画面（Visual）        | 同期声/访谈（Sync）      | 解说词（VO）              |
|-----------------------|--------------------------|---------------------------|
| 航拍：清晨的港口      | 汽笛声、工人吆喝         | "凌晨四点，港口醒了。"     |
| 特写：手上的老茧      | 老张："干了二十年。"      | （留白，让同期声说完）      |
```

- **规范**：三栏对齐；解说词**不与同期声抢话**；画面栏写"可拍到的具体内容"。
- **解说词三原则**：短句、给信息不给情绪、留白处不填词。
- **结构**：钩子（异常/悬念）→ 展开（人物/事件）→ 升华（不点破，留画面）。
- 自检：去掉解说词只看画面与同期声，是否仍能读懂？

## 二、音乐剧脚本

```
【曲目 3】歌名（时长）
【场景】地点·时间
【调度】（舞台走位/群舞位置）
角色A（唱）：
  〈唱词〉
角色B（说）：台词。
【重唱/合唱】（声部与进入点）
【舞台提示】灯光/道具/转场
```

- **规范**：**唱词（抒情/内心）与台词（推进情节）分工**——唱词不承担信息交代。
- **唱段类型**：I Want 歌（欲望）、I Am 歌（自我认知）、十一时刻歌（抉择）、重唱（冲突）。
- **结构**：一首歌 = 一次情绪位移（进场情绪 ≠ 出场情绪）。
- 自检：每首唱段是否推进了人物弧？纯装饰性唱段应删。

## 三、沉浸式戏剧 / 剧本杀脚本

```
【角色本】（每人一册，仅含本角色视角）
  身份 / 目标 / 秘密 / 已知线索 / 行动任务
【公共线索卡】（按轮次发放）
  线索ID / 内容 / 指向 / 解锁条件
【DM 手册】
  时间线（真实版）/ 触发条件 / 控场要点 / 结局判定
```

- **规范**：**角色本 = 私视角**（见 `deconstruction-mystery-game.md` 视角分割）；
  线索卡按"公开:私线 ≈ 6:4"发放。
- **DM 手册**是全知视角，含：真实时间线、何时发哪张卡、控场与救场。
- **自检**：信息公平（所有结论所需线索对玩家可见）；每个角色有唯一功能。
- 适配：短剧可用"剧本杀式"结构做多视角悬疑（见 `short-drama-genres.md`）。

## 四、三类共性自检

- [ ] 承载明确（纪录片=信息、音乐剧=音乐情绪、沉浸式=空间与信息博弈）
- [ ] 无越权：纪录片解说词不抢同期声；唱词不交代情节；角色本不含他人视角
- [ ] 有可执行交付物（三栏表 / 曲目单 / 角色本+线索卡+DM 手册）
- [ ] 结尾处理得当（纪录片留画面、音乐剧落在情绪、沉浸式给结局判定）

## 五、与本项目集成

- 纪录片解说词可用 `export_wechat_article` 转图文；音乐剧唱段对应 `Shot.sound`；
- 剧本杀角色本/线索卡的结构化字段可登记 `StoryState`（角色私线→characters；线索→foreshadowing）。
