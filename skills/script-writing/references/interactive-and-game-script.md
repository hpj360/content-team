# 互动剧 / 游戏分支脚本（形态深度）

> `script-writing` 按需加载参考。互动叙事与线性剧本的根本差异：**观众做选择，作者管状态**。
> 与 `deconstruction-mystery-game.md`（多视角机制）互补。

## 一、结构：节点图而非流水线

```
入口节点 → 选择A / 选择B → 各自分支 → 汇合点 → 结局（多结局）
```

- 用**节点（node）**为最小单位，每个节点含：场景描述 + 选项 + 跳转目标。
- 汇合点（merge）是控本关键：分支越早汇合，制作成本越低。

## 二、节点脚本格式

```
【节点 N07】地点·时间
（场景描述 / 画面）
角色A：台词。
—— 选项 ——
  [A] 追问真相      → 变量: trust+1   → 跳转 N09
  [B] 保持沉默      → 变量: trust-1   → 跳转 N11
  [C] 出示证据      （需 item=证据）   → 跳转 N14
```

- 选项必须**改变状态或路径**；只改台词不改路径 = 伪选项（观众会察觉）。
- 条件选项（需持有某物/某关系值）提升重玩价值。

## 三、状态系统（变量与旗标）

| 类型 | 用途 | 示例 |
|---|---|---|
| 数值变量 | 关系/信任/资源 | `trust`, `money` |
| 布尔旗标 | 事件是否发生 | `saw_letter = true` |
| 物品 | 证据/道具 | `item:证据` |
| 结局判定 | 由状态组合决定 | `trust≥3 且 saw_letter` → 真结局 |

- **结局判定表**：列出每个结局的进入条件，避免"唯一结局"或"随机结局"。
- 自检：所有变量都有"被读取"处（写而不用 = 死变量）。

## 四、多结局设计

- 结局数 3–5 为宜（真结局 + 2 个分支结局 + 1 个坏结局）。
- **真结局**需要最完整的状态组合（鼓励探索）；坏结局由关键失误触发。
- 每个结局都要**回应当初的选择**（让玩家感到"这是我的故事"）。

## 五、游戏对白脚本（差异）

- 对白常以**表格/JSON**交付：`node_id / speaker / line / condition / next`。
- 与系统耦合：台词可被本地化、被 UI 截断 → **单句长度受限**。
- 战斗/演出旁白与可交互对白分开标注（可跳过 vs 必须点击）。

## 六、自检清单

- [ ] 有节点图，且标注汇合点
- [ ] 每个选项都改变状态或路径（无伪选项）
- [ ] 变量/旗标均被读取（无死变量）
- [ ] 结局判定表完整（进入条件明确）
- [ ] 多结局（3–5）且各自回应选择
- [ ] 对白可被截断（单句长度受控）

## 七、与本项目集成

- 节点脚本可作 `Script`（`script_type=INTERACTIVE`）→ 分镜按节点拆；
- 状态变量与结局判定可登记 `StoryState.foreshadowing`（条件即伏笔）与
  `goals`（分支目标），由门禁校验埋设/回收。
