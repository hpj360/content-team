# 故事状态与连续性契约（蒸馏）

> 面向 `novel-writing` 的按需加载参考。蒸馏自公开长篇创作 skill 的"状态落盘/连续性管理"方法，重构为可执行契约，非逐字引用。
>
> **状态连续性分工索引**：角色档案与四维状态 → `character-bible.md`；
> 章际转场 / 叙述连贯 → `chapter-continuity.md`；
> 交接权责 → `skills/showrunning/references/production-contract.md`。

## 一、原则：状态落盘，跨会话一致

长篇最大的失败不是文笔，而是"人设漂移 / 伏笔不填 / 能力前后矛盾"。解法是把关键状态从上下文里拿出来，落成文件，作为**唯一权威**。

- 结构化状态是权威（JSON）；给人和模型看的 Markdown 是**派生视图**。
- 派生视图不进正文 prompt，只用于恢复与自检。
- 新会话开始时先读状态文件，再决定接下来写什么。

## 二、文件结构（建议）

```
项目/
├── 追踪/
│   ├── _tracking-state.json     # 唯一结构化权威状态
│   ├── 上下文.md                # 派生续写状态卡（固定栏位，≤12KB）
│   ├── 逐章记录/                # 每章未来相关的连续性记录
│   ├── 角色状态/                # 派生核心角色快照（一人一档）
│   └── 伏笔.md                  # 派生伏笔当前视图
├── 拆文库/{书名}/               # 拆文产物，写作的 source of truth
└── .active-book                 # 当前活跃书目相对路径
```

## 三、上下文状态卡（固定栏位）

`上下文.md` 固定 7 栏，便于快速恢复：

1. 当前位置（卷/章）
2. 近 5 章摘要
3. 活跃角色列表（含当前状态）
4. 待回收伏笔清单
5. 当前卷目标
6. 全局约束（不可违背的红线）
7. 下一步计划

## 四、角色状态契约

每个主要角色记录**进入状态**与**离开状态**，四个维度：

| 维度 | 说明 |
|---|---|
| 能力 | 当前实力/技能/装备 |
| 心理 | 目标、恐惧、关系倾向 |
| 关系 | 与其他核心角色的关系与信任度 |
| 目标 | 本卷内该角色的行动目标 |

- 角色变化必须可追溯：某章改变了什么 → 记录在"逐章记录"。
- 跨卷时对比进入/离开状态，防止能力突进或性格突变。

## 五、伏笔契约

- 每条伏笔字段：`id / 内容 / 埋设位置 / 计划回收位置 / 当前状态（已埋/进行中/已回收）`。
- **挖坑必填**：任何"已埋"伏笔都要有计划回收位置；无计划的不要埋。
- 每完成一卷，跑一次"未回收清单"，决定：回收 / 延期 / 明确放弃。

## 六、目标分层（防模糊）

- 全局约束：世界观红线、人设红线、平台合规。
- 当前卷目标：本卷要交付的情绪与主线推进。
- 本章目标：本章解决什么、抛出什么新问题。

三层必须同时存在于状态文件中，不能只留一个模糊的"继续写"。

## 七、机器可验证检查

- [ ] `_tracking-state.json` 可解析且字段完整
- [ ] 上下文状态卡 7 栏齐全
- [ ] 每个主要角色都有进入/离开状态四维记录
- [ ] 伏笔均有埋设与计划回收位置
- [ ] 未回收伏笔清单为空或已标注处置方式
- [ ] 全局约束/卷目标/章目标三层不缺失
